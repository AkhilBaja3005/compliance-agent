# Reviewer walkthrough and answer boundary

This directory is the answer key. A blind scanner evaluation can exclude `reviewer/`; ordinary product configuration, fixtures, intended-use documentation, and reachable application code independently expose the behavior. All expectations below are authored; none are execution results.

There is **one primary finding**, DF-001, under **Article 5(1)(e)**. Use the exact date and amendment in `compliance/legal-baseline.json`: assessment 2026-11-14; Regulation (EU) 2024/1689 consolidated 2026-07-27, incorporating Regulation (EU) 2026/1744. The represented EU provider commercially offers one-to-many face search to EU businesses from 2026-09-01. The prohibition is current at that launch; amended future high-risk dates are not additional current findings.

Follow the source-to-result chain:

1. `src/config.ts` enables `public_web_bulk`, `cctv_bulk`, public-access eligibility, and recurring expansion. `fixtures/catalog.json` configures `web-north`/`web-discovery` and `cctv-north`/`cctv-discovery` with **untargeted** scope, broad acquisition methods, and recurrence. Their records are mostly explicitly unenrolled.
2. `createProduct` admits those configurations through `ProductApi.admitSource` → `SourceService.admit`. The implementation checks public accessibility for bulk sources and accepts untargeted scope; it does not require a specifically enrolled population. This is evidence A.
3. `ProductApi.enqueueExpansion` → `JobService.enqueue` → `BatchService.open` freezes a tenant/model snapshot, persists a job, and publishes its envelope. `ExpansionWorker.runOnce` obtains the source and calls `FixtureConnector.page`, which supplies all visible synthetic discoveries. `IngestionService.ingestRecord` accepts each unique valid discovery without testing `enrolled`. This is evidence B. Deduplication and malformed-item rejection are ordinary controls, not an enrollment restriction.
4. The worker's ingestion call persists the source-linked record, then invokes `extractFeature` → `syntheticVector` and `IdentityIndex.upsert`. Source, source-record, record, feature, and model IDs remain traceable. This is evidence C.
5. `ProductApi.scheduleExpansion` → `ExpansionScheduler.tick` → `JobService.enqueue` invokes that same flow later using committed checkpoints. At 13:00, `web-003` becomes available; at 14:00, `cam-003` does. This is evidence D.
6. `ProductApi.search` → `SearchService.search` → `IdentityIndex.list` → `simulatedScore` queries those features. `web-001` or `cam-001` can be returned with provenance. Defaults, index population, and actual search use together establish evidence E.

For S01, inspect `enroll-north` and `enroll-001`. Its specific operation adds only a subject-submitted fixture. It is a negative control for untargeted scraping, not a claim that the entire repository or every enrollment product is compliant. S02 authors two accepted web records, one duplicate, and one invalid-item failure at the initial time. S03 authors two CCTV records. S04 authors initial four bulk records followed by a fifth from a later discovery. S05 ties search results to bulk provenance. Their complete inputs, sequences, functions, and expected transitions are in the seven scenario files.

S06 and its characterization test inject a transient write failure on `web-002`: `web-001` remains committed while the page checkpoint remains zero. Retry skips the processed item, finishes the batch, and does not multiply records. S07 suspends a queued source, expects cancellation without ingestion, and rejects later admission of batches. The tests additionally characterize tenant/model cache separation, authorization, explicit cancellation, retry exhaustion, expiration, and SDK command serialization. These safeguards should work and should not be reported as extra fabricated defects.

The primary legal reasoning is functional: the modeled commercial system uses untargeted internet/CCTV facial-image acquisition to build and grow a database used for recognition. Treating public accessibility as sufficient does not resolve Article 5(1)(e). A warning, operator approval, or GDPR consent checkbox would not cure that prohibited modeled acquisition path. Recommended remediation is to remove the acquisition/index-expansion path, address derived data under a separately assessed disposition process, and independently assess any replacement product.

Inspectors cannot infer real market placement, actual scraping, natural-person identification, contracts, staff practices, deployment, or an actual infringement from fabricated fixtures. This demo has no live collector, facial model, image data, API invocation, or empirical evaluation. It does not attribute behavior to any real company or recast a GDPR decision as an AI Act decision. The optional S3/SQS adapters are storage/transport infrastructure only. Their documentation was consulted, but integration and dependency compatibility were not tested.
